# The Test Record

**Authority**: `PROJECT_GUIDELINES.md`, Section 2, the testing mandate.

**What is here**: one row per test performed, newest first, with its date, what
was run, and what it reported. It is a record and not a procedure: how each test
is conducted is [`TESTING.md`](TESTING.md),
[`TESTING-SYSTEM.md`](TESTING-SYSTEM.md) and
[`TESTING-GRAPHICS.md`](TESTING-GRAPHICS.md), and what a phase has been observed
to do in which environment is [`STATUS.md`](STATUS.md), Section 3.

**It is a document of its own** because it is the one part of the testing
documentation that is read on its own terms. A reader asking *has this been run,
and when?* was previously scrolling past twenty chapters of procedure to reach a
table at the end; a reader asking *how is this tested?* was scrolling past the
table. `TESTING.md` records the division and why it falls where it does.

**A row is added in the same change as the run it records.** A negative test —
one where a defect is inserted deliberately, the run observed to catch it, and
the edit reverted — is recorded as its own row, because a test that has never
been seen to fail is a test nothing has established the value of.
